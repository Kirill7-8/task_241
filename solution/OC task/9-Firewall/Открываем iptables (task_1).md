## 3. Почему может пропасть такая возможность?
После установки или применения правил в `iptables` доступ по SSH может пропасть, если:
- Политика по умолчанию (default policy) для цепочки `INPUT` установлена в `DROP` или `REJECT`.
- Отсутствует явное разрешающее правило для SSH порта (обычно TCP/22).
- Активен другой фаервол (например, `firewalld` или `ufw`), который блокирует подключение
## 4. Откройте нужный порт на сервере чтобы восстановить подключение
```bash
sudo iptables -A INPUT -p tcp --dport 22 -j ACCEPT
```
## 5. Это будет udp или tcp порт?
SSH использует исключительно TCP-порт (обычно 22). UDP для SSH не применяется.
### Сохраняем

## 6. Сохраняются ли записанные вами правила после перезагрузки?
Нет, так как правила `iptables` хранятся в оперативной памяти и сбрасываются после перезагрузки сервера.
## 7. Как их сохранить?
```bash
sudo iptables-save | sudo tee /etc/sysconfig/iptables # сохраняем в файл конфигурации
```
